# Умный офис

Учебный проект по ПМ03, МДК 03.01. **Группа 54-15, Анфилатов Ярослав Дмитриевич.**

Виртуальный прототип «умного офиса»: датчики температуры и влажности в Node-RED, автоматическое
включение вентилятора в серверной при температуре выше 30 °C, приём показаний на сервере
приложений и хранение истории в базе SQLite.

## Как устроено

**Датчики (ПР №4).** В Node-RED на IOT-01 два узла `inject` с ручным вводом: «Температура, °C»
(по умолчанию 35) и «Влажность, %» (45). Введённые числа повторяются каждые 5 секунд и уходят
двумя POST-запросами: на приёмник CTRL-01 (`/api/readings`) и в хранилище DB-01.

**Вентилятор (ПР №5).** То же значение температуры идёт в `switch`: выше 30 °C — `change`
собирает `fan.state = ON`, иначе `OFF` (`actuator_id` = `FAN-01`, `zone` = `server_room`,
`mode` = `auto`). Узел `rbe` пропускает событие только при смене состояния.

**База (ПР №6).** `practice6/server.py` принимает POST и пишет в SQLite две таблицы:
`measurements` (показания) и `actuator_events` (события вентилятора). Схема создаётся вручную
файлом `schema.sql` — сервис её только проверяет. Веб-интерфейс — `index.html`.

**Мониторинг (ПР №7).** На MON-01 Prometheus и Grafana установлены как системные службы.
Prometheus каждые 5 секунд опрашивает `http://192.168.40.10:8080/metrics` (задача
`office-controller`), Grafana показывает панель преподавателя и следит за возрастом показаний:
если датчик молчит дольше 20 секунд при живом CTRL-01, правило уходит в Alerting и пишет
письмо на контакт Email. Пропажа самого CTRL-01 отслеживается отдельным правилом по `up`.

Отправку писем выполняет SMTP-сервер, заданный на MON-01 в `/etc/grafana/smtp.env`
(параметры подключения и пароль приложения в репозиторий не входят). Адрес получателя указан
в провижининге контакта `Email` только на стенде; в репозитории лежит обезличенный вариант.

## Схема обмена данными

```
 IOT-01 (192.168.50.10)                     CTRL-01 (192.168.40.10)
 ┌───────────────────────────┐              ┌──────────────────────────────┐
 │ Node-RED :1880            │  POST        │ приёмник :8080               │
 │  inject «Температура»     │ /api/readings│  • проверяет поля запроса    │
 │  inject «Влажность»       │─────────────►│  • хранит последние значения │
 │  switch > 30 °C           │  POST        │  • журнал docker compose     │
 │  change ON / OFF          │ /api/actuators  • GET /metrics              │
 │  rbe «только при смене»   │─────────────►│                              │
 └─────────┬─────────────────┘              └──────────────┬───────────────┘
           │ POST /api/readings, /api/actuators             │ GET /metrics (5 с)
           ▼                                               ▼
 ┌───────────────────────────┐              ┌──────────────────────────────┐
 │ DB-01 (192.168.40.12)     │              │ MON-01 (192.168.40.11)       │
 │ хранилище :8081           │              │ Prometheus :9090             │
 │ SQLite telemetry.sqlite3  │              │  └─► Grafana :3000           │
 │  measurements             │              │        • панель датчиков     │
 │  actuator_events          │              │        • правила Alerting    │
 │ веб-страница истории      │              │        • письмо на Email     │
 └───────────────────────────┘              └──────────────────────────────┘
```

Показание рождается в Node-RED, уходит параллельно на CTRL-01 и DB-01, а Prometheus забирает
его с CTRL-01 по `/metrics`. Grafana ничего не принимает от датчиков: она только читает
Prometheus. Поэтому остановка Grafana не влияет на приём и запись данных.

## Как проверял

* ПР №1–2 — план и схема открываются в remplanner.ru и draw.io; с WIN-01 проходят ping
  до IOT-01 и трёх серверов РЕД ОС (0 % потерь).
* ПР №3 — Docker и Compose на CTRL-01, DB-01, IOT-01; Nginx отвечает `200 OK` на 8080
  и через `docker run`, и через `docker compose`; порт после проверки освобождён.
* ПР №4 — `/health` приёмника отвечает, Node-RED открывается с WIN-01, оба датчика присылают
  показания каждые 5 секунд, приёмник пишет их в журнал.
* ПР №5 — `35` даёт `ON`, `29` даёт `OFF`; в журнале приёмника видны оба состояния.
* ПР №6 — `sqlite3 3.40.0` на DB-01, контейнер `practice6-storage-1` в состоянии `healthy`,
  в базе больше 1100 показаний и только реальные переключения вентилятора; страница
  `http://192.168.40.12:8081/` показывает те же значения, что и журнал CTRL-01.
* ПР №7 — `promtool` принимает конфигурацию, цель `office-controller` в состоянии UP;
  на панели видны 38 °C, 45 %, ON, AUTO и возраст показаний около секунды; после остановки
  TEMP-01 возраст вырос до 60 с, HUM продолжал обновляться, правило TEMP-01 стало Alerting
  и письмо пришло в ящик `grafana-alerts`; после остановки CTRL-01 цель стала DOWN, а значения
  датчиков исчезли с панели вместо показа последних известных.
* ПР №8 — 19.11.2026 проверены показания каждые 5 секунд, переключение вентилятора при 29, 30
  и 31 °C, появление строк в SQLite и отображение на панели; остановка TEMP-01 и HUM-01 по
  отдельности дала рост возраста, сохранение `up = 1`, переход правила в Alerting и письмо
  с названием датчика в ящике; после восстановления все правила вернулись в Normal. Проверки —
  в `evidence8/`, журнал испытаний — в `journal.md`.
